## Why this matters

The end goal lists "YouTube links, device files, text files, and PDFs" as inputs. Paste a podcast or video link and
get a transcript; import a PDF or a Word document and turn it into notes. After this milestone, "Paste a link" on the
Capture screen is real.

## Scope

- **In scope:** a link classifier; podcast and direct-media download (to `media/<id>/source.<ext>`, with real
  progress, off the speech scheduler); YouTube captions; YouTube audio behind a toggle **only if the owner approves**;
  a `document` path (PDF text + OCR, TXT/MD/RTF/HTML, DOCX) producing a Library item without audio; new dependencies
  (e.g. ZIPFoundation) recorded in THIRD_PARTY_LICENSES; privacy table rows; contracts for document items.
- **Must not change:** the transcription pipeline after the file exists; the media layout (additive); privacy
  defaults (`personal`); no network access except on an explicit user action.
- **Out of scope:** in-app browsing, playlists, background downloads after the app closes (consider after M1.5 patterns).

## Steps

### Step 1: Link classifier and download manager

Classify a pasted or shared URL: Apple Podcasts episode, podcast feed, direct media (by extension or content type),
YouTube, other (unsupported with a clear message). Downloads use `URLSession` with progress into the item's media
folder, cancellable, resumable where the server allows. Downloads never occupy a speech-scheduler slot.

**Verify:** classifier table tests; download tests against a local `URLProtocol` stub (no real network in tests).

### Step 2: Apple Podcasts

Port upstream: `https://itunes.apple.com/lookup?id=<showId>&entity=podcastEpisode&limit=200`; match the `?i=` episode
id from the share link against `trackId`; fall back to the RSS feed. Then import the downloaded file with
`sourceType: .podcast`.

**Verify:** resolver tests with recorded JSON fixtures (synthetic, no personal data); device: paste a real episode.

### Step 3: YouTube, captions first

Port the youtube-transcript-api method: watch page → `INNERTUBE_API_KEY` → `/youtubei/v1/player` as the `ANDROID`
client → caption track `baseUrl` → timed text. Store as a `url` item with segments from caption timing (no audio
player). If there are no captions, say so and offer Share/import of a file the user has.

**Before any YouTube audio download:** write the options and the terms-of-service note in the PR/hand-off and get
the owner's decision. If approved, add YouTubeKit (verify its license) in `.local` mode only (never its remote
fallback server), behind a Settings toggle, off by default.

### Step 4: PDF

`PDFDocument` text per page; pages without text are rendered to images and read with Vision
`RecognizeDocumentsRequest` (iOS 26). Result: a `document` item with page-numbered text.

**Verify:** tests with generated PDFs (text and image-only pages created at test time).

### Step 5: Text documents

TXT and Markdown as UTF-8; RTF and HTML via `NSAttributedString`; DOCX by unzipping (ZIPFoundation) and reading
`word/document.xml` paragraphs. Result: `document` items.

**Verify:** fixtures generated at test time; malformed files fail with a clear error.

### Step 6: UI

Paste a link sheet (paste button, detected type, progress, errors); document rows in Library with a document cover;
a document detail view (text, no player) that M4 templates can use.

## STOP conditions

- YouTube audio download without the owner's recorded decision.
- A dependency with a GPL-incompatible license (route through [ADR-010](../../spec/adr/010-plugin-license-gate.md)).
- Any request that would send user content (not just the link) to a third party.

## Maintenance notes

- YouTube's internal API changes without notice; keep the caption client small and its failure message clear.
- Podcast episode ids from share links do not resolve directly; matching against the show's episodes is intentional.
