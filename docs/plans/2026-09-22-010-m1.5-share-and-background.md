## Why this matters

In M1 a long recording stops transcribing the moment the owner switches apps, and the only way in is the file
picker. The owner's real inputs are Voice Memos and files other apps hand them. This milestone makes the two
everyday paths work: share a Voice Memo to Parakeet, lock the phone, and find the finished transcript later, with the
system's own progress UI while it runs.

## Current state (verified live at `721db7e8`)

- `ChirpFeatures.FileTranscriptionPipeline` (actor, `FileTranscriptionPipeline.swift`):
  `importFile(from:sourceType:) async throws -> UUID` copies (security-scoped, on its file queue) into
  `media/<id>/source.<ext>` and inserts a `.processing` row; `@discardableResult process(id:) async -> Transcription?`
  runs the job and returns the row as saved (`.completed`, `.failed`, `.cancelled`) or nil; `retry(id:)` moves a
  failed/cancelled/interrupted row back to `.processing` and re-runs it. Progress is `JobProgress(stage:fraction:)`
  through the `onProgress` **init parameter**; stages are `importing, queued, normalizing, waitingForEngine,
  transcribing, identifyingSpeakers, finishing`, fractions never decrease within a run. Normalization is
  `normalizer.normalize(sourceURL:outputURL:)`.
- `ChirpFeatures.TranscriptionJobCenter` (`@MainActor @Observable`): `start(fileAt:pipeline:)`,
  `retry(_:pipeline:)`, `cancel(_:)`, `isRunning(_:)`, `waitUntilIdle()`, `progress[UUID]`, `lastImportError`, and
  `progressHandler` (the pipeline's `onProgress`; hops to the main actor). The transcription id is unknown until
  import returns, so jobs are tracked by an internal token.
- `App/Sources/AppEnvironment.swift` builds everything; `launch()` runs `markStaleProcessingAsInterrupted()` then
  `sweepOrphanedTemporaryAudio()` once per process; `importFiles(_:)` awaits `launch()` then calls
  `jobCenter.start` per file; `retry(_:)` calls `jobCenter.retry`. Callers: Capture's `.fileImporter`, and the Retry
  buttons in Capture, Library and Transcript.
- `project.yml`: one app target `iChirp`, no extensions, no entitlements file; Info.plist properties include
  `LSSupportsOpeningDocumentsInPlace: false` but **not** `UIFileSharingEnabled` (the original plan said it did).
  `App/Info.plist` is generated from `project.yml` by XcodeGen and is tracked in git.
- `App/Sources/Support/DownloadKeepAlive.swift` (idle timer off plus `beginBackgroundTask`) wraps the Settings model
  Download taps and the DEBUG smoke runner's launch-argument auto-download.
- `ChirpAudio.AVAudioNormalizer` decodes the **first** audio track through `AVAssetReaderAudioMixOutput`.
- `ChirpStore`: one migration, `v1-transcriptions`; `TranscriptionRecord` mirrors every `Transcription` field.
- `spec/02-features.md` says "Until M1.5 a long file pauses when the app leaves the foreground, and the UI says so";
  no such copy exists in the app. M1.5 replaces the sentence rather than adding the copy.
- Salvage candidates in `legacy/gemini-ios/` (present): `Sources/MacParakeetMobileUI/Extensions/ShareExtensionHandler.swift`,

## Refinement (2026-09-22, at `721db7e8`)

**Apple facts, verified** against the iPhoneOS 26.5 SDK headers shipped with Xcode 26.6
(`BackgroundTasks.framework/Headers/BGTaskRequest.h`, `BGTaskScheduler.h`, `BGTask.h`), Apple's article
"Performing long-running tasks on iOS and iPadOS", and WWDC25 session 227 "Finish tasks in the background":

- **Wildcard identifiers are accepted.** `BGTaskRequest.h` on `BGContinuedProcessingTaskRequest.init`: the identifier
  "ought to use wildcard notation": the bundle id, optional semantic context, then `.*` in
  `BGTaskSchedulerPermittedIdentifiers`; the submitted identifier replaces `*` with a dynamic suffix. WWDC25-227 says
  the same ("continued processing tasks support a new wildcard notation with a dynamic suffix").
- **No `UIBackgroundModes` value and no entitlement** for CPU / Neural Engine work. Apple's article, the header and
  the session name only `BGTaskSchedulerPermittedIdentifiers`. The only entitlement is
  `com.apple.developer.background-tasks.continued-processing.gpu`, for `requiredResources = .gpu`, which Parakeet does
  not request. If the device ever answers a submission with `notPermitted`, that is a STOP: adding `processing` to
  `UIBackgroundModes` is an Info.plist-only change, but it is the owner's call.
- **Registration.** Continued-processing launch handlers are exempt from "register before launch finishes"; register
  right before `submit`. Registering the same identifier twice kills the app, so the dynamic suffix is a fresh UUID
  per submission (not the transcription id: Retry reuses the id).
- **Behavior.** The launch handler may run while the app is still in the foreground (DTS, forum thread 802073), so the
  job starts immediately and the system task is only a keep-alive and progress surface. Tasks reporting little
  progress are terminated first. The expiration handler runs when the person taps Cancel in the Live Activity or the
  system expires the task; call `setTaskCompleted(success:)` in every case. Force-quitting from the app switcher
  cancels running tasks with no callback (the next launch marks the row `interrupted`). The Simulator does not run
  background tasks (`BGTaskScheduler.Error.unavailable`). In this SDK `submit(_:)` throws synchronously.

**Design decisions (change the letter, not the intent, of Steps 1, 2 and 4):**

- **One continued-processing request per user action, not per file.** A batch pick or Retry becomes one request whose
  progress is the mean of its jobs' fractions. Per-file tasks would leave files queued behind a long one reporting
  no progress, and the system terminates those first. Identifier: `"\(Bundle.main.bundleIdentifier!).transcribe.\(UUID())"`.
- **The Settings model Download tap** gets its own request (`….download.<UUID>`), as the final-review I3 correction
  above asks. `DownloadKeepAlive` stays for two cases the task cannot cover: when the system refuses the request, and
  the DEBUG smoke runner (a launch argument is not a person's tap, which Apple requires).
- **Testable core.** The mapping (monotonic aggregate progress, completion, expiration → cancel) lives in
  `ChirpFeatures` behind two small protocols and is tested on the Mac with fakes; only
  `App/Sources/Support/ContinuedProcessing.swift` imports `BackgroundTasks`.
- **Step 1:** incoming files switch to the Capture tab so the new Recent row is visible; the `Documents/Inbox` copy is
  deleted once its import settles or the track picker is dismissed (never a path outside `Documents/Inbox`).
- **Step 4:** the picker appears only for two or more audio tracks. A file with no audio track, or one whose tracks
  cannot be read, keeps M1's behavior (a row is created and fails at normalization with the existing message):
  upstream rejects those before a row exists, but "Must not change" below protects M1's error semantics. An
  explicit ordinal that a later file in the batch lacks fails that file ("This file has no audio track N"), never
  falling back. Retry reuses the stored ordinal. Migration `v2-audio-track-ordinal` (name coordinated with the M4
  lane, which adds its own).
- **Carried M0/M1 review items** (model unload and memory-warning response, deleting a previous model version's
  files) are not in this lane's scope (Steps 1, 2 and 4); they stay open for a follow-up.

## Carried from M0/M1 review

- The temp-audio sweep (`FileTranscriptionPipeline.sweepOrphanedTemporaryAudio`, run at launch) only protects jobs
  started by this process. It matters here specifically if the Share extension (Step 5) ever runs its own jobs
  rather than handing off to the main app — confirm the sweep still covers (or is duplicated for) whichever process
  actually creates temp audio.
- `ChirpEngineFluidAudio` model assets never unload once loaded, and nothing responds to a memory warning (Minor 3);
  the device benchmarks show a 2.3 GB first-run peak. Since this plan is the first to add sustained background
  execution (Step 2's `BGContinuedProcessingTask`), design the unload path and memory-warning response here rather
  than after background jobs exist.
- Switching Parakeet model version in Settings leaves the previous version's files (~470 MB) on disk with no Delete
  affordance (Minor 9, second half). Worth fixing alongside the unload path above, since both touch
  `ModelAssetLifecycle`'s on-disk bookkeeping.

## Steps

### Step 1: "Open in Parakeet" from the Share sheet (no extension, no account change)

Declare audio and movie document types so Parakeet appears in the Share sheet's app row for Voice Memos and Files:
`CFBundleDocumentTypes` for `public.audio` and `public.movie` (role Viewer, handler rank Alternate) in `project.yml`.
Handle incoming file URLs with SwiftUI `.onOpenURL`: start security-scoped access, call the pipeline's import, then
start processing through `TranscriptionJobCenter`. The system's `Documents/Inbox` copy is a temporary file the app may
remove after the import succeeded (it is not user data; the imported copy in `media/<id>/` is).

**Verify:** `scripts/gen.sh && scripts/test.sh` green; on the device (`scripts/run_device.sh`), Voice Memos → Share →
Parakeet → a Recent row appears and completes.

### Step 2: Long jobs continue in the background (`BGContinuedProcessingTask`)

When the user starts a job (import or share), also submit a `BGContinuedProcessingTaskRequest` from the foreground:

- Identifier derived at run time: `"\(Bundle.main.bundleIdentifier!).transcribe.\(UUID())"`, one request per user
  action (refined: a fresh UUID per submission, see "Refinement"); declare the wildcard
  `$(PRODUCT_BUNDLE_IDENTIFIER).transcribe.*` (and `….download.*` for the Settings model download) in
  `BGTaskSchedulerPermittedIdentifiers` (never hard-code the prefix).
- Register the launch handler at submission time (not at app launch). In the handler, map `JobProgress` to the
  task's `Progress` (the system expires tasks that do not report progress), set an `expirationHandler` that cancels
  the job (row → `cancelled` or `interrupted`, never lost), and call `setTaskCompleted(success:)`.
- Strategy `.queue` by default.
- Title and subtitle come from the file's display title; the system shows its own Live Activity with Cancel.

During refinement, confirm in Apple's current documentation whether any `UIBackgroundModes` value is required and
whether the task request needs anything beyond the Info.plist identifiers. If it needs an entitlement or capability,
STOP (account change).

**Verify:** unit-test the progress mapping with a fake pipeline; on the device, import a 20-minute synthetic file
(`say -f` a long text into an `.m4a`), lock the phone, and confirm the job finishes with the system progress UI.

### Step 3: Measure background inference on the owner's iOS version

On iOS 26 the Neural Engine is available in the background. On iOS 27 it is not without
`com.apple.developer.background-tasks.continued-processing.inference`. Record in a dated
`docs/research/<date>-background-inference.md`: iOS version, whether the job continued, throughput in foreground vs
background, and any Core ML error. If the phone is on iOS 27 and inference fails in the background, STOP and report:
the options (request the entitlement = account change; CPU fallback = reload the encoder with CPU compute units) are
the owner's decision.

### Step 4: Choose the audio track for multi-track files

Port the upstream audio-track semantics (one-based for users, zero-based ordinal among audio tracks, a single track
needs no picker, two or more require a choice before any row or work exists). Add `audioTrackOrdinal` (nullable) to
`AudioNormalizing.normalize` through an additive overload, a new migration, and a picker sheet in the app. Write
`spec/contracts/file-transcription-audio-tracks-v1.md` from the upstream contract, adapted.

**Verify:** `scripts/check.sh ChirpAudioTests` with a generated two-audio-track `.mov` fixture (built in `setUp`).

### Step 5 (gated): Share extension with an App Group inbox

Only if Steps 1–2 leave a real gap (for example sharing URLs, or importing without opening the app) **and** the owner
approves the account change: an explicit App ID with the App Groups capability for the app and the extension. With
approval, add target `iChirpShare` in `project.yml`, reuse the salvaged `ShareExtensionHandler` logic, derive the App
Group ID at run time, load no models in the extension, and write a contract for the inbox manifest. Weigh it against
the extension budget in [ADR-008](../../spec/adr/008-distribution-and-build-identity.md).
