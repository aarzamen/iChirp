## Why this matters

Dictation is the owner's most frequent task: press the Action Button, speak a note, get clean text on the clipboard.
MacParakeet's defining rule carries over: live text is only a preview; the text you get comes from a final Parakeet
pass over the recording, which is more accurate. The Gemini port got this backwards (its "final" text was the last
partial), which the review rejected.

## Steps

### Step 1: Audio session and shared microphone stream (`ChirpAudio`)

Port the semantics of upstream `SharedMicrophoneStream` (one engine per process, fan-out to subscribers, tap buffer
4096 frames) onto iOS, re-reviewing the salvaged `IOSMicrophoneEnginePlatform` and its tests. `AVAudioSession`
`.playAndRecord` activated in the foreground; interruption handling (resume only on `.shouldResume`); route-change
rebuild on `AVAudioEngineConfigurationChange` that **re-installs the tap** (the upstream silent-stall lesson);
media-services reset. Hide `AVAudioSession` behind a protocol so package tests run on the Mac.

**Verify:** `scripts/check.sh ChirpAudioTests` with a fake session platform: interruption began/ended(shouldResume),
route change re-taps, reset recovers.

### Step 2: Recorder

Port `AudioRecorder`: 16 kHz mono Float32 WAV via `AVAudioConverter`, channel-0 rule under voice processing, reject
recordings shorter than 0.3 s, write into `media/<id>/dictation.wav` (additive to the media layout contract; update it).

**Verify:** feed synthetic buffers (from a `say` fixture) through a fake stream; the WAV has the expected duration ±1%.

### Step 3: Live session contract and tail-window preview

Add a `LiveSpeechSession` protocol to `ChirpCore` (begin, append samples, partial text stream, finish, cancel;
display-only). Update [`speech-engine-plugin-v1.md`](../../spec/contracts/speech-engine-plugin-v1.md) additively.
Implement the upstream tail-window preview for Parakeet: every ~1 s transcribe the last ~15 s, single-flight (skip a
tick while one is running), through the scheduler's interactive path, cancelled and drained on stop. Port
`LiveTranscriptStabilizer` (append-only display, last 3 words tentative).

**Verify:** stabilizer tests ported with upstream names; a preview test with a fake engine proves single-flight and
cancel-on-stop.

### Step 4: Dictation coordinator (final pass)

Port the upstream flow as a state machine (`idle → recording → stopping → done | failed | cancelled`): on stop, cancel
the preview, append 0.5 s of silence for short clips, run `.dictation` on the recorded WAV, run `TextRefinement` with
the user's clean-up mode, custom words and snippets, save a `dictation` row (audio kept per a new setting), and copy
the text with `UIPasteboard` (iOS cannot paste into other apps). Empty text → `emptyTranscript` shown as "Didn't catch
that".

**Verify:** `scripts/check.sh ChirpFeaturesTests`: state machine transitions; the copied text equals the final
pass output, not the last partial; cancel leaves no row; failure keeps the audio and offers Retry.

### Step 5: Custom words and snippets

New migration adding `custom_words` and `text_snippets` (upstream fields), stores, and the Settings → Text editor.
The pipeline's `customWords` closure reads the store.

**Verify:** store tests (in-memory DB); Clean mode applies a custom word end to end in a pipeline test.

### Step 6: Dictating screen and Capture wiring

Build the Dictating screen from the handoff: night background, live text (tentative tail dimmed), waveform from real
levels, timer, Cancel / Stop & copy / Polish after. "Polish after" = run Clean for this dictation. Replace the Dictate
card placeholder. Copy correction: "Press the Action Button, or tap to go hands-free."

**Verify:** `scripts/run_sim.sh` screenshots vs the canvas; on the device, dictate 20 s and paste into Notes.

### Step 7: Action Button, App Shortcuts, Live Activity (widget extension)

Add one widget extension target (Live Activity + a Control) in `project.yml` with `NSSupportsLiveActivities = YES`.
A start intent conforming to `AudioRecordingIntent` must **start a Live Activity when recording begins and keep it
while recording**, or iOS stops the recording. Use `supportedModes` (not the deprecated `openAppWhenRun`); try
`.foreground(.immediate)` first. Stop intent ends the activity after the final pass. The Live Activity shows state,
elapsed time and Stop. App Shortcut phrases for "Dictate with Parakeet". The owner assigns the shortcut or Control to
the Action Button in iOS Settings; Settings → Capture explains how (and how to use Back Tap, which is an iOS
Accessibility setting the app cannot set).

**Verify:** on the device: Action Button starts dictation from the Lock Screen and from another app; the Live
Activity appears in the Dynamic Island; Stop copies the final text.

### Step 8: Background and iOS 27

Add `UIBackgroundModes: audio`. Recording must start in the foreground (a Control/intent brings the app forward).
Record in `docs/research/` what happens when the final pass runs while the app is in the background on the owner's
iOS version (Neural Engine on iOS 26; restricted on iOS 27).

## STOP conditions

- The design needs an entitlement or capability beyond the widget extension's plain bundle id (App Groups, Siri,
  push): owner decision.
- `AudioRecordingIntent` cannot start from a Control on the device without opening the app, and no acceptable UX is
  left: report findings with options.
- Any path would make the copied text differ from the final pass output.
- A route-change or interruption test cannot be made deterministic (report timing instead of adding sleeps).

## Maintenance notes

- Keep the preview single-flight; a queue of previews starves the final pass.
- Voice-processing I/O changes channel layout; keep the channel-0 rule from upstream.
- The live-session protocol is the seam for M7 streaming engines; do not special-case Parakeet in the coordinator.
