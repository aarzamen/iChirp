**Goal:** Parakeet reads text aloud — deliverables, transcripts, Ask answers and dictation read-back — in the owner's
local ChoiceVoice/Kokoro voices (through the Mac companion) or Grok voices (xAI).
**Architecture:** one plug-in target `ChirpEngineVoiceHTTP` with two `SpeechSynthesizing` conformers ported from the
owner's Readback app; a `VoicePlayer` in ChirpFeatures that chunks, synthesizes ahead and plays through M2's
`AudioSessionController`; Settings → Voices; privacy routing on every call.
**Tech stack:** Swift 6, URLSession, AVFoundation (`AVAudioPlayer` or `AVAudioEngine`), Keychain (`ChirpKeychain`).
**Spec:** [design 018](2026-09-22-018-design-companion-voice-needle-jev.md) §2,
[speech-synthesis-plugin-v1](../../spec/contracts/speech-synthesis-plugin-v1.md),
[mac-companion-v1](../../spec/contracts/mac-companion-v1.md).

## Global constraints

- Repo is **public**: never commit API keys or the owner's cloned voice id (Readback hard-codes it in
  `XAIProvider.cloneVoice`; do NOT copy that line — the phone gets a free-text Voice ID field instead).
- Port from Readback (`~/readback/Sources/TTS/*.swift`, `Sources/Audio/PlaybackEngine.swift`) with the header
  `// Ported from Readback (owner's project): <path> @ <readback short sha>` and a one-line change summary.
- Routing: `PrivacyRoutingPolicy` before every synthesis; clinical → trusted companion only, or a per-run confirmation
  for xAI (reuse M4's `PrivacyOverrideRequest`/confirmation pattern); logs carry ids, counts and `kindName` only.
- Swift 6 strict concurrency; strict lint clean; focused tests only; own simulator (`iChirp-l2`); no physical iPhone;
  no new capability or entitlement; commit per step; **no assistant trailers**; no push.
- Merge coordination: new files; small additive edits to AppEnvironment, SettingsScreen, TranscriptScreen,
  DocumentScreen, the Ask view, `project.yml`, `Package.swift`. Plan 019 builds the companion server and Settings →
  Mac companion (host/port/token/trusted); read that configuration through a small protocol so this lane does not
  wait for it (a fake in tests).

## Drift check (2026-09-22, lane L2)

`git diff --stat dd7fd56f..HEAD -- ChirpKit/Sources/ChirpCore/Engines ChirpKit/Sources/ChirpAudio
ChirpKit/Sources/ChirpKeychain App/Sources/Screens` is empty (the lane starts at the planned-at commit), and
`SpeechSynthesizing` in `ChirpCore/Engines/SpeechSynthesis.swift` matches speech-synthesis-plugin-v1. No STOP.
Refinements that keep the approach but pin where things live (engine targets depend only on ChirpCore; the audio
session lives in ChirpAudio; ChirpFeatures imports no engine):

- **Ports split by module.** `TTSProvider`/`TTSHTTP`, `XAIProvider` and `OpenAIProvider` (the OpenAI speech shape,
  which the companion speaks) → `ChirpEngineVoiceHTTP` (`XAIVoice`, `CompanionVoice`, `VoiceHTTPTransport`).
  `Chunker` and `SynthQueue` → `ChirpFeatures` (`SpeechChunker`, `VoicePlayer`), as Step 3 says. `PlaybackEngine` →
  `ChirpAudio` (`SpeechPlaybackEngine`, through `AudioSessionController`) behind a small ChirpCore protocol
  `SpeechAudioPlaying`, so `VoicePlayer` is tested with a fake player. `ElevenLabsProvider` is not ported (the owner
  chose companion + Grok voices only).
- **`CompanionConfiguration` lives in ChirpCore** (`Engines/CompanionConfiguration.swift`): host, port, trusted flag
  and the pairing token as a `SecretValue`, read at every call. `CompanionVoice` (an engine target) can only see
  ChirpCore; plan 019's Settings → Mac companion store conforms to it when lanes merge. Until then the app wires an
  unconfigured stand-in, and tests use a fake.
- **Locality of the companion follows its host** (`LocalNetworkHost.isLocal`), like M4 providers: a companion address
  that is not on the local network counts as `cloud` for routing, so "trusted" can never cover an internet host.
- **The clinical confirmation for voices is `VoicePlayer`'s own single-use request**, not `DeliverableService`'s
  (whose `PrivacyOverrideRequest` is bound to a transcription and a language model). Same shape and wording pattern
  ("Read this clinical text aloud with Grok voices?"), per utterance, never remembered. The app dialog mirrors
  `ClinicalConfirmation` and gets its own structure test; it must not call anything named `confirmOverride(` (M4's
  structure test pins that name to the Transform/Ask dialog).
- **Playback yields to recording:** `AudioSessionController` already tells `.playback` observers
  `.interruptionBegan` when dictation or a meeting activates `.recording`; `SpeechPlaybackEngine` pauses on it and
  never resumes by itself, exactly like the transcript `PlayerBar`. Dictation and meeting code is not touched.
- **Temporary audio** goes to `tmp/speech-<utterance id>/` (a random id, not a hash of the text), deleted when the
  utterance ends and swept at launch except the live utterance's folder.

## Steps

### Step 1: `ChirpEngineVoiceHTTP` — xAI
Port `XAIProvider` as `XAIVoice: SpeechSynthesizing` (id `xai.tts`, locality cloud, host `api.x.ai`): stock voices,
`validate()` via `/v1/api-key`, key from `SecretStoring`, refuses redirects, maps HTTP errors onto
`SpeechSynthesisError`. Port `TTSHTTP` error scrubbing (the key never appears in an error).
**Verify:** focused tests with a URLProtocol stub: request shape (JSON body, Bearer header), 401/429/5xx mapping,
empty audio, redirect refused, key never in errors.

### Step 2: `ChirpEngineVoiceHTTP` — companion
`CompanionVoice: SpeechSynthesizing` (id `companion.speech`, locality localNetwork) for the companion's
`POST /v1/audio/speech` and `GET /v1/voices` per mac-companion-v1; configuration (host, port, token) injected through
a `CompanionConfiguration` protocol (plan 019 provides the real one); `availability()` caches `GET /v1/companion` for
30 s; `style` → `instructions`.
**Verify:** stub tests for the speech request, voice list parsing, 401/413/503 mapping, availability caching.

### Step 3: `VoicePlayer` (ChirpFeatures)
Port `Chunker` (sentence boundaries under `maxCharactersPerRequest`) and `SynthQueue` (synthesize chunk n+1 while
chunk n plays; previous/next text passed along). `VoicePlayer` (`@MainActor @Observable`): `speak(text:privacyClass:
source:)`, `pause`, `resume`, `stop`, state (`idle`, `preparing`, `speaking(chunk, of)`, `failed(message)`), routing
check first (clinical + cloud → confirmation; refused → a clear message, nothing sent). Plays through
`AudioSessionController` (playback category; stops when dictation or a meeting starts). Temporary audio under
`tmp/speech-<hash>/`, swept at launch.
**Verify:** tests with a fake engine and a fake player: chunk order, prefetch of exactly one chunk ahead, stop cancels
pending synthesis, routing refusal sends nothing, a clinical + cloud request waits for confirmation.

### Step 4: Settings → Voices
Provider picker (Mac companion, Grok voices), per provider: voice list (companion voices come from the companion;
Grok stock voices plus a free-text **Voice ID** for a cloned voice), style field (companion), xAI key field (Keychain),
Test voice (speaks a fixed synthetic sentence), default voice. Honest states: companion not configured / not reachable,
key missing.
**Verify:** view-model tests; simulator screenshots.

### Step 5: Listen everywhere
**Listen** button on `DeliverableDetailScreen` (and the Transform result), on `TranscriptScreen` (reads the transcript
from the tapped paragraph onward), and a "Speak answers" toggle in Ask; a mini now-playing bar with pause/stop.
Expose `VoicePlayer.speak` for plan 015's dictation "read back" command.
**Verify:** app tests for the Listen availability states; simulator run against a stub server; screenshots.
