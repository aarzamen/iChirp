# R1 review — domain, persistence, export (ChirpCore, ChirpStore, ChirpKeychain, ChirpExport)

Commit 53bc2cc6, branch `main`. Read-only review; nothing was built or run.

## Overall assessment

The safety core is solid. `PrivacyRoutingPolicy` is correct for every class × locality × override combination: it fails
closed on a missing host, and a cloud engine can never be trusted. The `SpeechJobScheduler` slot and continuation
invariants hold, including the cancel-versus-grant races. Migrations are additive and have upgrade tests. Unknown enum
values fall back to the protective choice, store logs carry ids only, and the Keychain store is small and correct. The
weak spots are scale and fidelity, not routing:

- **Scale.** The transcript store decodes every column of every row (word timings, segments, PDF pages) on every change,
  and it rewrites the whole row for a one-field edit.
- **Fidelity.** That whole-row rewrite also silently drops newer-build JSON data, which a contract promises to keep.
- **Export drift.** The export layer has drifted from its own contracts and ADR: the JSON omits its arrays, Clean mode
  is ignored for timed items, PDF/Word uses a second Markdown parser, and VTT is not escaped.

Two more medium items: a PHI-residue gap (live-preview WAVs left in tmp after a kill) and a cross-build path that can
wipe every saved language-model provider. The rest are test gaps, naming and doc drift.

### R1-1 [medium] [performance/scalability] — Every change to any transcript re-decodes the whole library's JSON; Capture decodes everything to show 3 rows
- **Where:**
  - `ChirpKit/Sources/ChirpStore/GRDBTranscriptionStore.swift:25` (all-column `newestFirst`), `:146-150` (`fetchAll`),
    `:173-194` (`observeAll`), `:124-137` (`modify`).
  - Consumers: `ChirpFeatures/LibraryViewModel.swift:229-256`, `ChirpFeatures/CaptureViewModel.swift:7,26-36`
    (`recentCount = 3`).
  - Id-only use: `ChirpFeatures/Dictation/DictationCoordinator.swift:630`. Retention: `ChirpFeatures/Meeting/MeetingAudioRetention.swift:69`.
  - Write cadence: `ChirpFeatures/Meeting/TranscriptNotesViewModel.swift:37` (autosave 800 ms after typing).
- **Problem:**
  - `observeAll()` tracks the whole `transcriptions` table. After every committed write to any row it runs
    `Row.fetchAll` of all columns and `decodeRows`, which JSON-decodes `wordTimestamps`, `speakers`,
    `diarizationSegments`, `transcriptSegments` and `documentPages` for every row.
  - Two observers run: Library and Capture. Each also calls `fetchAll()` at start.
  - At launch, `recoverOrphanedRecordings` decodes the whole library just to collect ids, so the library is decoded
    about five times per launch (six with retention on).
  - The `AsyncStream`s use the default unbounded buffer, so a busy main actor queues whole-library snapshots.
  - `modify` (favorite, title, privacy class, notes, status) decodes and re-encodes the entire row for a one-field
    change.
- **Failure scenario / evidence:**
  - Word timings are about 90 bytes of JSON per word, which with segments is roughly 1 MB of JSON per recorded hour.
  - With a 100-hour library, typing in a meeting's Notes tab costs, at every 800 ms pause, one ~2 MB whole-row rewrite
    plus two full-library decodes (~100 MB of JSON each).
  - `LibraryViewModel.items` keeps every word of every recording in memory for the app's lifetime. That memory is then
    missing from `os_proc_available_memory`, so `checkMemoryFit` refuses Whisper loads sooner.
  - Contrast: the deliverables side already solved this (`DeliverableListingQueries.summaries`: `substr(text,1,320)`,
    columns read by position, a 5,000-row performance test). Transcripts have no equivalent.
- **Fix:**
  - Add a `TranscriptionSummary` list query: the row columns plus the text search needs, no JSON columns.
  - Add `fetchIDs()` / `exists(id:)` for the existence checks and `fetchRecent(limit:)` for Capture.
  - Use `.bufferingNewest(1)` on both observe streams.
  - Turn the field-level writes into column-level `updateAll(Column(...).set(to:))`, which also fixes R1-2.
  - Tests: a synthetic 300 × 1-hour library performance test mirroring `testThousandsOfDocumentsListAndSearchQuickly`,
    and an assertion that `updateFavorite` leaves the stored `wordTimestamps` text byte-identical.
- **Confidence:** CONFIRMED for the mechanism (traced). The magnitude is PLAUSIBLE: estimated, not measured on a device.

### R1-2 [medium] [data integrity/contract] — Field-level writes re-encode every JSON column, so a newer build's page `method` and unknown JSON keys are silently overwritten
- **Where:**
  - `ChirpStore/GRDBTranscriptionStore.swift:124-137` (`record.toTranscription()` → `TranscriptionRecord(row)` →
    `update`).
  - `ChirpStore/TranscriptionRecord.swift:169-189`: `keepingUnknownRawValues` covers only `sourceType`, `status`,
    `privacyClass` and `documentFormat`.
  - `ChirpCore/Models/Document.swift:55-59` (an unknown method reads as `.textLayer`).
  - `spec/contracts/document-items-v1.md:92-93`: older builds "read unknown values as nil / `textLayer` and keep them on
    write".
  - The ChirpStore README rule: "Writes never overwrite a value this build could not read".
  - Same pattern: `ChirpStore/GRDBTextRulesStore.swift:89,121` (an unknown `source` reads `.manual` and an unknown
    `action` reads nil, and `save` writes those fallbacks back).
- **Failure scenario / evidence:**
  1. A newer build stores `documentPages = [{"number":1,"text":"…","method":"handwriting"}]`, or adds a key such as
     `"isFiller":true` to a `WordTimestamp`.
  2. On an older build the person stars, renames, edits notes or marks the item clinical.
  3. `modify` re-encodes `"method":"textLayer"` and drops the unknown key.
  4. Back on the newer build, `ocrPageCount` and the extra word data are gone.

  `DocumentColumnsMigrationTests.testUnknownDocumentFormatReadsNilAndIsKeptOnWrite`
  (`ChirpStoreTests/DocumentColumnsMigrationTests.swift:88-107`) puts `"future-method"` into `documentPages`, but
  asserts only that `documentFormat` survived. An assertion on the pages would fail today.
- **Fix:**
  - Fields that do not live in JSON get column-level SQL updates (no decode or encode).
  - `renameSpeaker` patches the `speakers` / `transcriptSegments` JSON through `JSONSerialization`, so unknown keys
    survive.
  - Extend the existing test to assert that the raw `documentPages` text survives `updateFavorite`.
- **Confidence:** CONFIRMED.

### R1-3 [medium] [correctness/spec contradiction] — In Clean mode, TXT/Markdown/PDF/Word exports of any timed transcript use the raw words; Copy uses the cleaned text
- **Where:**
  - Code: `ChirpExport/TranscriptExporter.swift:125-144,148-173` (the word path never reads `cleanupMode`) and
    `ChirpExport/ExportDocument.swift:86-99`.
  - Specs it contradicts: `spec/adr/009-deterministic-cleanup-raw-default.md:23` ("Its output is `cleanTranscript`; copy
    and export use it") and `spec/07-text-processing.md:67` ("Text follows the clean-up mode").
  - `ChirpExport/README.md:66` documents the opposite. Copy follows the mode
    (`ChirpFeatures/TranscriptViewModel.swift:66-74`).
- **Failure scenario:**
  - The owner turns on Clean with a custom word ("zarelto" → "Xarelto") and filler removal.
  - Copy of a dictation gives "Xarelto 20 mg daily".
  - Share → Text, Markdown, PDF or Word of the same item gives "um zarelto 20 mg daily", because every audio item has
    word timings.
  - The three Clean-mode tests (`TranscriptExporterTests.swift:296-330`) use rows without words, so they never exercise
    the real path.
- **Fix:**
  - The owner decides which rule stands, then code and docs are made to agree.
  - If ADR-009 stands: in Clean mode with a non-empty `cleanTranscript`, build the TXT/MD/PDF/DOCX paragraphs from the
    clean text, and keep the words for SRT/VTT/JSON.
  - Test: a Clean-mode export of a row that has words plus a custom-word-corrected `cleanTranscript` contains the
    corrected spelling.
- **Confidence:** CONFIRMED.

### R1-4 [medium] [contract/export] — `ichirp.transcript/v1` omits `speakers`, `segments` and `words` instead of writing empty arrays; the contract's round-trip tests do not exist
- **Where:**
  - `ChirpExport/TranscriptExporter.swift:240-253,266-268`.
  - Producers of nil: `ChirpFeatures/FileTranscriptionPipeline.swift:587,628`.
  - Contract: `spec/contracts/transcript-json-v1.md:36-38` and `:59`.
  - Tests: `ChirpExportTests/TranscriptExporterTests.swift:206-238`.
- **Problem:**
  - The JSON payload struct declares these three keys as optional arrays, and synthesized `Encodable` omits nil keys.
  - The pipeline sets `speakers = nil` without diarization and `transcriptSegments = nil` when there are none, and
    documents have no words.
  - The contract types all three as "array" (`speakers`: "empty when no speakers"). Only the scalar fields may be
    absent or null.
- **Evidence:**
  - Exporting a file transcribed with speaker labels off gives JSON with no `speakers` or `segments` key, so
    `doc["speakers"]` raises a KeyError in a script.
  - The contract cites "JSON round-trip cases ported from upstream `ExportServiceTests`". Only `testJSONSchemaKey` and
    `testJSONIncludesCoreFields` exist, and they decode scalar keys only.
- **Fix:**
  - Encode `speakers ?? []`, `segments ?? []` and `words ?? []`.
  - Add tests that decode with non-optional arrays for a speakerless row and for a document row, plus a words and
    segments round trip that checks the `wordRange` indexes.
- **Confidence:** CONFIRMED.

### R1-5 [medium] [privacy/data at rest] — Live-preview windows of the person's speech are written to `<tmp>/live-preview-<uuid>.wav` and never swept after a kill
- **Where:**
  - `ChirpCore/Engines/SpeechEngineRouter.swift:383-391`.
  - The launch sweeps in `App/Sources/AppEnvironment.swift:384-404` have no entry for it, and the string
    `live-preview-` appears nowhere else.
- **Problem:**
  - Apple Speech and WhisperKit have no live mode of their own, so the router previews them by writing the last 15 s of
    audio to tmp on every pass.
  - Each pass then awaits `live.prepare()` and transcribes. Deletion is only a `defer`.
  - If the process dies in between, the audio stays in tmp: a jetsam during the Whisper load (the case fix/speech-memory-fit
    targets), a crash, or a force-quit.
  - Every comparable temp artifact is swept at launch: export folders, voice-message chunks, spoken-instruction
    recordings (review M3), benchmark copies (review M6) and normalized WAVs.
- **Failure scenario:**
  1. The owner dictates a clinical note with Whisper Turbo on the live route.
  2. iOS kills the app during the first model load inside a preview pass.
  3. A WAV of the patient encounter stays in tmp indefinitely.
- **Fix:**
  - Write windows into a dedicated `<tmp>/live-preview/` folder.
  - Call `prepare()` before writing.
  - Sweep the folder in launch housekeeping.
  - Test: a stale file in that folder is removed by the sweep, and a sibling file is not.
- **Confidence:** CONFIRMED.

### R1-6 [medium] [correctness/maintainability] — PDF/Word export parses generated Markdown with its own ad-hoc parser that disagrees with ChirpText's `MarkdownBlockParser`
- **Where:**
  - `ChirpExport/ExportDocument.swift:114-151,177-207`.
  - Template section style: `ChirpFeatures/BuiltInTemplates.swift:84-94,133-136` (`**Subjective**`,
    `**Action Items**`).
  - Copy and on-screen text use `ChirpText/Markdown/MarkdownBlock.swift:42` (with `PlainTextFlattener`).
- **Problem / failure scenarios:**
  - (a) A model following the SOAP template writes `**Subjective**` on its own line. `ExportDocument.text` treats it as
    body text and merges it with the next line. A SOAP note's PDF/DOCX therefore has no section headings and no
    keep-with-next.
  - (b) `"# of doses given: 3"` and `"#1 priority"` (no space after `#`) become level-1 headings and lose the `#`.
    CommonMark requires the space.
  - (c) `clean()` deletes every `__`, so `"Signature: ________"` prints as `"Signature: "`. Also `"2**10"` becomes
    `"210"`.
  - (d) Nested lists are flattened.

  This is a different code path from the known Copy-flattener item, so fixing `PlainTextFlattener` will not fix it.
- **Fix:**
  - Build `ExportDocument` blocks from `MarkdownBlockParser.parse` plus `MarkdownInline.plain`. ChirpExport already
    depends on ChirpText.
  - Tests: `"**Subjective**\nCC: cough"` gives a heading and a paragraph; `"#1 priority"` stays a paragraph with its
    `#`; `"Signature: ______"` is kept.
- **Confidence:** CONFIRMED for (a), (b) and (c) (traced). That models actually emit (c) is PLAUSIBLE.

### R1-7 [medium] [data integrity/cross-build] — Language-model provider settings decode strictly: one unknown provider kind hides every provider, and the next save erases them
- **Where:**
  - `ChirpCore/Models/LanguageModelProvider.swift:5,51` (synthesized `Codable` on `LanguageModelProviderConfiguration`).
  - The destructive half is in ChirpFeatures, `LanguageModelProviderStore.swift`:
    - `load()` at `:149-155` returns `Stored()` when decoding fails.
    - `save(stored)` at `:85,97,124,138` writes that empty value back.
- **Failure scenario:**
  1. A newer build saves a provider with `"kind":"gemini"`.
  2. On an older build the whole blob fails to decode, and Settings → Models shows no providers.
  3. Adding a provider or changing the default writes back a blob holding only that one.
  4. Every other provider, with its trusted-LAN flag, is gone, and their API keys are orphaned in the Keychain.

  The codebase decodes `TranscriptionSettings` and `SpeechRouteSelection` forgivingly for exactly this multi-build
  reason; this type is the exception.
- **Fix:**
  - Decode providers one by one; skip unknown entries but keep their raw JSON for write-back.
  - Never save over a blob that failed to decode.
  - Test: a blob with one unknown-kind provider and one known provider loads the known one, and saving another keeps
    the unknown entry.
- **Confidence:** CONFIRMED (traced). It triggers only once a future build adds a kind.

### R1-8 [low] [correctness/export] — WebVTT cue text and voice annotations are not escaped
- **Where:** `ChirpExport/TranscriptExporter.swift:198-201`, a faithful port of upstream
  `ExportService.swift:349-354`.
- **Failure scenario:**
  - `"<5 mg"`: in the WebVTT tokenizer, `<` followed by a digit opens a timestamp tag. It runs to the next `>`, so "5 mg"
    (and the `</v`) disappear in conforming players.
  - A renamed speaker such as `"A>B"` (rename allows any 60 characters) yields `<v A>B>…`. The voice becomes "A" and
    "B>" leaks into the text.
  - `&` in `"Q&A"` makes the file invalid, although players are lenient about it.
- **Fix:**
  - Escape `&`, `<` and `>` in cue text and annotations, and replace newlines in labels.
  - Test with a cue "dose <5 mg Q&A" and the label "A>B".
- **Confidence:** CONFIRMED in the code. How often the raw words contain `<` is PLAUSIBLE.

### R1-9 [low] [correctness/export] — Export file names can exceed the 255-byte file-name limit, and the two stem helpers disagree
- **Where:**
  - `ChirpExport/TranscriptExporter.swift:90-95` has no length cap.
  - `ChirpExport/DocumentExporter.swift:44-49` caps at 120 Characters (not bytes) and falls back to "document" where the
    other uses "transcript".
- **Failure scenario:**
  - PDF titles up to 200 characters are kept (`ChirpIngest/Documents/DocumentTextExtractor.swift:130`), and renames
    are unbounded.
  - A 100-character Japanese title is 300 UTF-8 bytes. `write` throws "file name too long" and Share fails with a
    generic error, in both exporters.
- **Fix:**
  - One shared stem helper that truncates on a Character boundary to at most ~200 UTF-8 bytes.
  - Test both exporters with a 150-character CJK title.
- **Confidence:** CONFIRMED.

### R1-10 [low] [privacy] — `LocalNetworkHost` reads leading-zero IPv4 octets as decimal ("010.0.0.1" → 10/8 → LAN)
- **Where:**
  - `ChirpCore/Models/LanguageModelProvider.swift:175-185`.
  - `ChirpCoreTests/LanguageModelProviderTests.swift:20-38` has no leading-zero case.
- **Problem:**
  - inet_aton-style resolvers and the WHATWG URL parser read "010" as octal 8, giving 8.0.0.1, a public address.
  - The type promises "anything it does not recognize is treated as the internet".
  - Such a host passes `validate()` with `http://`, can be marked trusted, and clinical text then routes to it without
    the confirmation.
- **Fix:**
  - Treat any octet with a leading zero as not local.
  - Add "010.0.0.1" and "0177.0.0.1" to the not-local test list.
- **Confidence:** The misclassification is CONFIRMED. What iOS's resolver actually connects to is PLAUSIBLE, not
  verified.

### R1-11 [low] [tests] — Four scheduler tests order their jobs with `Task.sleep(50/20 ms)`
- **Where:** `ChirpCoreTests/SpeechJobSchedulerTests.swift:13-19,30,40-42,54-58`.
- **Problem:**
  - `testBackgroundJobsRunByPriorityThenFIFO` assumes `fin` is enqueued within 20 ms.
  - On a loaded runner the gate opens first and the order becomes `[blocker, live, finalize, file2]`, a spurious

  from the blocking job.
- **Confidence:** CONFIRMED.
